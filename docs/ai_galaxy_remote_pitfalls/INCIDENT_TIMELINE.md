# 历史事件时间线（脱敏）

本时间线只保留可复用的工程事实，不包含密码、token、私钥或完整登录信息。

## 事件 1：旧实例与正式实例混淆

- 曾有一台旧的 2080 Ti 相关实例，使用过 19524 端口，后来已释放。
- 正式任务使用的是另一台 16 CPU / 32 GB、实际 GPU 为 RTX 3080 的实例，使用过 13212 端口。
- 教训：必须按 provider 实例详情、SSH 端口和硬件联合确认，不能沿用聊天中的旧地址或预期 GPU。

## 事件 2：主机内存 OOM

- 正式任务初版在 16c32g 上被系统杀死。
- 失败类型是主机 RAM OOM；进程匿名 RSS 约 30.3 GiB，不是单纯 CUDA 显存不足。
- 改为流式输出、有界分块、推理模式和内存上限后，正式任务完成；实际完成时间约 929.91 秒。
- 教训：必须保留失败事实；只有完整输出和退出证据才能进入完成状态。

## 事件 3：handoff 滞后

- handoff 一度仍显示运行中，但远程任务已经生成完整结果。
- 教训：handoff 不能作为唯一状态来源，要回到进程、manifest、报告和校验结果。

## 事件 4：自动续租与释放

- 平台原生自动续租曾处于开启状态并产生自动续费记录。
- 结果收集和 SHA256 校验完成后才释放实例；释放后核对了运行实例数和保留磁盘数。
- 教训：平台原生续租必须显式核对，释放后还要查账单；不能用外部 watchdog 代替平台生命周期管理。

## 事件 5：本地回收审计

- 结果进入独立 retrieval 目录，远程 manifest 与本地文件逐一校验。
- 远程结果没有在未获用户决定前删除。
- 当前项目交付仍遵守生信隔离：不读取、不更新、不重建 `infra/bioinf-data-index/`。
