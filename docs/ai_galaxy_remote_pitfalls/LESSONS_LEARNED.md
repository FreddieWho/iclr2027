# AI Galaxy 远程实例：问题与经验

## 1. 实例身份不能靠 IP 或“当前只有一台机器”判断

曾出现过旧的 19524 端口实例和后续正式任务使用的 13212 端口实例；硬件、任务状态和 provider 所属状态并不应由聊天中的旧地址推断。正式任务还出现过“用户以为是 2080 Ti、实际实例详情为 RTX 3080”的认知偏差。

**风险**：把任务发到错误机器、查看错日志，或释放错误合同。

**规则**：

- 下单后重新读取 provider 实例列表和实例详情；核对 `instance_name`、SSH 端口、GPU、CPU、内存、状态和创建时间。
- 释放前按实例唯一标识和 SSH 端口交叉核对，不能按 IP、账号下唯一运行实例或聊天记录释放。
- `nvidia-smi` 是远程实际 GPU 的补充证据；不能把计划中的 V100/2080 Ti 当成实际硬件。

## 2. SSH 凭据曾被暴露，不能进入项目文件

历史对话中出现过 SSH 密码。密码、token 和私钥不能复制进 README、脚本、YAML、日志、handoff 或提交记录。

**规则**：

- 优先使用 SSH agent 或安全凭据存储；确需临时传递时使用权限为 `0600` 的临时文件，任务后立即清理。
- 使用任务专用 `known_hosts`，启用 `StrictHostKeyChecking=yes`。
- 禁用共享控制 socket（`ControlMaster=no`、`ControlPath=none`），避免不同任务相互复用会话。
- 远程工作优先使用普通项目账号；root 仅用于明确的系统级设置。

## 3. OOM 是主机内存 OOM，不是 GPU OOM

正式任务曾在 16 CPU / 32 GB RAM 实例上被系统杀死。日志显示 `pt_main_thread` 的匿名 RSS 约 30.3 GiB，属于主机内存耗尽；不能仅检查 CUDA 显存来判断安全。

**原因**：一次性保留完整 JSON/delta 数组、响应对象和模型中间结果，16c32g 没有足够的系统内存余量。

**修复原则**：

- manifest 和响应按有界 chunk 流式读写，不把完整任务展开到内存。
- 推理使用 `inference_mode`，分块执行，并及时释放模型和缓存；不需要 decoder 时不加载 decoder。
- 设置进程内存上限和预留空间（历史修复使用过 `MemoryHigh=24G`、`MemoryMax=28G`），但这不是替代内存预算的办法。
- 先跑与正式任务相同数据结构的 bounded smoke，再决定是否租用；smoke 成功不等于正式任务已完成。
- 若被 OOM，结论必须是 `INCOMPLETE`/`BLOCKED`，不能把部分输出包装成完成结果。

## 4. GPU 不是所有阶段都需要

本项目主线数据已经是点集。视觉网络（ResNet/DINO/OpenCLIP 等）不能从现有点集恢复缺失的朝向或笔画信息，只能作为有明确科学问题时的辅助路线。

P2-A/P2-B 的主要工作是支持集枚举、频谱特征计算、匹配和统计前置验证，CPU 足够且更适合快速迭代。GPU 只在实测表明正式多模型、多能量推理或 AMR 训练成为瓶颈时使用；不能因为“有 GPU”就扩大任务范围。

租用前必须同时估计：上传时间、启动/环境核验时间、正式计算时间、下载与校验时间以及自动续租的费用风险。

## 5. 平台自动续租和外部监控不是一回事

历史实例曾启用 AI Galaxy 原生自动续租，出现自动续费记录。平台原生开关、外部定时任务和 agent watchdog 是三个不同层次，项目不应自行实现一个隐藏的定时下单/续租器。

**规则**：

- 下单时明确核对 `autorenew`/续租状态和到期模式；不需要续租时显式关闭。
- 任务完成后先收集并校验结果，再释放合同；不要依赖到期自动停止。
- 释放后检查具体实例状态、费用/退款、账号运行数和 `kept_disks`。

## 6. handoff 状态可能滞后于真实任务

历史 handoff 一度仍写着 `RUNNING_NOT_COMPLETE`，但远程任务实际上已经完成。handoff 是导航文件，不是完成证据。

**规则**：完成判断必须由进程退出码、最终输出清单、报告和校验结果共同支持。每次状态更新都写入时间戳、实例标识、最近日志位置和产物状态。

## 7. 释放必须晚于收集和校验

历史正式任务的正确顺序是：远程生成 SHA256 清单 → 下载结果/报告 → 本地逐文件校验 → 审计可用性 → 释放实例 → 再查费用和保留磁盘。远程结果未经过本地校验时不能释放。

**规则**：

- 下载前先取得远程 manifest；禁止无清单盲目复制。
- 默认不覆盖已有本地结果；发生同名文件时写入新 retrieval 目录。
- 释放后主机短时间仍可连接不代表合同仍在计费；provider 状态和账单是释放事实来源。
- 未经用户决定不删除远程结果或保留磁盘。

## 8. 时间和性能不能用未经测量的线性外推

历史正式远程任务在修复内存策略后约 929.91 秒完成，但此前 CPU 估算不是 GPU 基准。不同 GPU、数据规模、上传速度和模型批大小会改变总时间。

**规则**：用同一代码路径、同一输入格式和同一输出格式做 bounded smoke，记录 wall time、峰值 RAM、峰值 VRAM 和输出大小，再给租用建议。所有未实际运行的性能数字标记为估计值。

## 9. 项目隔离不可省略

远程任务只允许使用本项目声明的点集/向量输入和代码。不要为了“更新索引”访问生信目录，不要把其他项目的缓存、known_hosts、凭据或模型输出混入本项目。每次远程交付应记录输入来源、代码版本、配置、产物哈希和隔离检查结果。
