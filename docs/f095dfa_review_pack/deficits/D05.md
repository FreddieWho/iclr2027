# D05｜原生实用视觉语言模型：在能看懂的任务上检验组合失效

## 目标及与旧支线的区别
旧DINO实验是“冻结编码器＋我们训练的读出＋抽象细线几何”。本实验直接测试原生多模态模型，在其能识别基本实体/关系的输入上是否出现同实例的原子—联合失配。不是再换一层DINO，也不把基础识别差当组合机制证据。[R04,R11]

## 模型和任务合同
选择一个可复现、可授权的开放模型做reference，例如Qwen2.5-VL-3B-Instruct；这是明确版本示例而非声称当前最强。执行前核实权重、license、revision、processor、tokenizer与生成设置。另一模型只在第一模型形成可解释结果后做异族确认。
任务先用具有清楚对象身份、可见关系的受控图像：粗实物形状的相对位置/接触/遮挡，或明确角色的足球图像。必须有独立oracle；生成器不是根据模型回答造难题。各图单独询问完全相同问题，禁止把A/B/AB一起给模型提示其逻辑。

## 步骤
1. 在开发父场景做基本实体、关系、语言输出probe，检查是视觉、语言还是结构问题。只允许一次明确的可读性修正并记录，不能搜几十种prompt挑最佳。
2. 预先选择主问题和解析器；原生zero-shot为主，少量in-context示例作为独立arm，示例只来自train。
3. 固定模型后生成一个未用于选择的parent银行，所有原子与联合状态均评价，不因错误类型难看而删除。
4. 主比较和小模型使用同一E/J/迁移定义；native模型不做repair时不编造repair结论。
5. 如需比较规模，最多同一家族两档，固定图与prompt，不能混用不同输入分辨率而称scale law。

## 输出规则
报告原子准确率与eligible覆盖、J、CCM、拒答/格式失败、每实例成本。原始文字与解析结果都存；格式失败计入总风险且另列，不静默排除。只有能获取可比token概率且二元答案合同稳定时才做P1；自报“我很自信”不能替代概率。
不强迫85%通过才报告，按照基础能力、分母大小和区间决定可支持的范围。若不具备基础视觉能力，结论为该输入接口不适合，不推广组合机制。

## 强结论的最低内容
模型已能可靠辨认相关原子，而同一E银行仍存在实质联合失效，且简单提示/自然静态对照不能完全解释。否则写边界或转向D04/U06，不无限换模型。交付 `D05_NATIVE_BRIDGE.md`、原始响应、失败解析审计、版本与成本清单。主文必须区分“原生实用模型评测”与“预训练模型下游适配”。
