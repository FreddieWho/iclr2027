# 06｜并行实施和“什么时候值得继续”

## 阶段不是审批门
下面只是工作节奏。没有一个阶段要求用户确认或统一显著性才能继续；发现好的结果可立即跨阶段，资源不足可缩小。

### 接线循环
总控写简短CAMPAIGN_STATE，确认当下可用场景/权重、算力和worker；W0接adapter与共同oracle；其他worker直接在内核/受控场景工作。接线预算用于能运行新试验的最小接口，不整理整个仓库。

### 第一轮：尽快看见六条路线的性质
- W1：R01同边际分布风险比较。
- W2：R02语义改变但表征/预测保持。
- W5：R05缓存表示+少量关系诊断。
- W6：R06生成器与最低动态模型试跑，安排空闲资源。
- W3：共享模板的源→目标小矩阵，可独立建立第一版源端矩阵。
- W4：用初始模式库的minimax/等权训练小试，不等其他路线“通过”。

最多3个重计算worker同时执行；轻量源文献/读出求解无需占满训练槽。可以顺序替代并行，不依赖某个特定provider。

### 第二轮：概念性迭代，不追着旧指标扫参数
每条路线根据实测决定：扩大场景/模式、换一个真正改变机制的任务或分布、与更强近邻比较、或停止。不能因为一轮效果没达预期数字就反复调epsilon；epsilon可作为明确的扰动强度维度展示曲线，但不能用最有利强度代替全部结果。

一个有意义的新构造失败可试合理的另一构造。若理由只剩“再多跑几次也许会赢”，关闭该支。无统一kill threshold，无强制10 seeds。

### 集中阶段
选择一个主发现＋一个方法；其余分支不必全部完成。理由按“能否改变论文主张、区别已有研究、带来真实任务后果、资源能否撑起”写一段即可。
对胜出路线，用没有参与其设计选择的剩余场景/新生成种子或新模型作评价；没有时标探索，不虚构独立确认。无需全项目重新分割或预注册。

## 本轮什么不做
不会先审计所有旧指标，不以齐全数据/全模型、预注册、文献40篇、统计p阈值为开工门。必要新对照只检验胜出主张，不要求各分支都跑全套。

## 每轮结果卡不超过两页
模板字段：一句新事实；设计改变；支持/反对证据；效应分母/成本；最强替代解释；下一步；能替换哪张图。机器明细另存。

## 资源与停止
本包没有授权新的收费资源，也没有假定当前一定有GPU。默认复用用户现有授权；一次费用请求写明任务、预计资源、上限及本地替代，其他分支继续。
模型总控可停昂贵无信息作业；不要为了“跑满6路”耗尽资源。若当前主线证据最好，允许最后选择不改稿；但必须是试过高价值新问题后的判断，而非预先把探索压回旧框架。

## 推荐交付清单
首轮：`CAMPAIGN_STATE.md`、最多6份结果卡、数据/模型接口、真实试验输出。
集中阶段：胜出故事1页、主图源表、方法代码和决定性对照、失败支路摘要。
收尾：`PAPER_REPLACEMENT_PLAN.md`、可直接填实际数字的摘要、run入口和依赖，不写假阳性结果。
