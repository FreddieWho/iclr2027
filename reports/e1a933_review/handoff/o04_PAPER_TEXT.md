## 总判定

**核心问题（"S/J/J\* 分解能否前瞻预测干预影响哪一段"）→ NOT_FOR_PAPER（作为正面主张）。**
理由：事前声明的主要预测在严格判据下**未全中**（P1 7/8，primary verdict = MISS），且分段归属随特征空间参数化改变（whitened 下 P1 仅 4/8）。把它写成"分解能前瞻指导干预"属于过强表述。

## 可用片段 A：head 级变化监督与主干级变化监督是替代关系（附录级）

中文草稿（一句话结论，可直接引用）：

> 在新任务（T1 点在三角形内，2724 E-quartet / 322 parent；T2 线段与圆盘，3443 E-quartet / 369 parent）上，冻结主干后仅改变读出层的监督（加入单编辑状态、两组各半权）只在主干本身**未**见过变化监督时带来联合正确率增益：T1 six_clean 的 J 由 0.1946 升到 0.2841（3 seed 均值，parent-equal ΔJ = +0.0638，同 parent 配对）、T2 six_clean 由 0.6952 升到 0.7441（ΔJ = +0.0337）；而主干已用变化监督训练时同一干预不再带来增益（T1 six_flip ΔJ = −0.0115，T2 six_flip ΔJ = −0.0016，J 已分别达到 0.7483 / 0.9993）。

> 在原始坐标主干上，同一读出层干预的 ΔJ 在 4/4 个单元上为负（−0.0141、−0.0341 等，3 seed 均值），说明该干预并非普遍有益。

**可以说**
- "读出层的变化监督只在表示层未含变化监督时有增益"——限定在 T1/T2、`raw`/`six` 两类参数化、convex L2-logistic 与 {16,64} 宽 MLP 读出、3 seed。
- "两级变化监督是替代关系而非叠加"——限定为上述单元内的经验观察。
- "该干预不是普遍有益"——raw 主干 4/4 单元 ΔJ 为负。

**不可以说**
- 不能说"变化监督的增益可加/可叠加"。
- 不能说"这是普遍规律"或"跨任务复制"：只有 2 个新任务 × 3 个共享任务/银行的 seed，不是独立任务数。
- 不能说"所有非线性读出都如此"：MLP 只测了 width ∈ {16,64}、300 轮 Adam，且 96 个候选里 77 个的 dev 最优落在第 300 轮（预算顶格）。
- 不能说"新银行独立确认"：T1/T2 主干与银行是既有 f095 产物，本 lane 只训练读出层。

## 可用片段 A2：开发集选出的阈值不随干预自动改善（附录边界句）

中文草稿：

> 在同一批冻结主干上，用 103 个 head-dev parent 的单状态准确率选出的阈值再拿到评估 quartet 上时，联合正确率可以远低于该 score 的 oracle 上界：T1 的 six_flip 主干配 static 读出层时 `J_dev`=0.4574 而 `J*`=0.7905（2724 E-quartet / 322 parent，3 seed 均值）；T2 同单元为 0.8921 对 0.9995（3443 / 369）。加入变化监督后 `J_dev` 分别升到 0.7796 / 0.9946，而 S 与 `J*` 基本不动。

**可以说**
- "在该任务上，开发集选出的阈值可能远低于 oracle 上界，且该差距与 S、J\* 无关"——限定为上述单元与 103-parent dev 规模。
- "变化监督可以只改善工作点而不改善上界"——对应预注册的 P2（|ΔJ\*| < |ΔJ|）在 8/8 单元成立。

**不可以说**
- 不能说"阈值选择是主要问题"或"标定失败是普遍现象"：只有两个任务、每个 3 seed，且 `J_dev` 不是预注册的三段之一，属事后观察量。
- 不能把 `J_dev` 与 `J*` 的差距当作可部署性能损失量（`J*` 用评估真值）。

## 可用片段 B：分段归属与 S 都是 S(f_head∘h) 的性质，不是主干的固有属性（正文/附录边界句）

中文草稿：

> 同一批冻结主干、同一批评估 quartet，仅把读出层的特征空间从"按 fit parent 标准化"换成"同一 fit 协方差白化"，"干预主要影响哪一段"的判定就从 8 个单元中 7 个归属 J 变成只有 4 个（其中 T1/raw_clean、T1/raw_flip、T2/raw_flip 的 argmax 段变成 oracle 上界 J\*，且干预幅度本身被放大，如 T1/six_flip 的 ΔJ 从 −0.0115 变成 +0.3484）。因此 S 与分段归属都必须写成 S(f_head∘h)，不能当作编码器的固有属性。

**可以说**
- "S 与分段归属随读出层的特征空间参数化改变"——有同数据、同主干、只换 head 参数化的直接对照。
- "J\* 是诊断上界，不是部署准确率"——全部 J\* 用评估真值选公共阈值。

**不可以说**
- 不能说"某个 encoder 天然地把干预引到 J 段/ S 段"。
- 不能把白化下的 ΔJ = +0.3484 当作方法效果，它只是同一干预在不同参数化下的读数，且伴随 J\* 同步上升（+0.1396），属于工作点/上界一起移动。

## NOT_FOR_PAPER 清单

1. **"S/J/J\* 分解是有效的前瞻干预诊断"** —— 作为正面主张不进稿。primary verdict = MISS（P1 7/8），且 whitened 参数化下 P1 仅 4/8，归属不稳定。
2. **任何"分解能预测干预动哪一段"的一般句** —— 只在 pipeline 条件内成立，且条件本身（head 家族、特征空间）就能翻转结论。
3. **"head 级变化监督修复了塌缩/修复了读出"** —— 本 lane 没有塌缩诊断，也没有修好任何东西；raw 主干上 ΔJ 全为负。
4. **"分解解释/预测了 D10 的覆盖塌缩或不可行份额"** —— 保持 **NOT_FOR_PAPER**（正面主张），原因：
   - **实际结论**：分解对 R09 的结果只能给"段位归属"——R09-B 显示同覆盖下 dev 阈值已近 oracle 前沿（差 ≤0.0093），收益主要来自覆盖从 0.15–0.20 推到 0.24–0.41；这与本 lane 的 P2（`|ΔJ*| < |ΔJ|` 在 8/8 单元成立）同形，说明杠杆在工作点/覆盖段，不在上界。R09-C（取消 dev 端可行性筛选后覆盖 0.3412–0.6059）把塌缩主要归于 dev/eval 目标错位。
   - **不能解释份额，且是结构性不能**：oracle 不可行 117/256 = 45.7% 的场景对全部 49 个候选都不可行，没有正状态；S/J/J\* 的定义域要求每 case 至少一个正/负状态，生产函数 `threshold_certificate` 对全负输入直接抛 `ValueError`（已实测）。这些场景不在分解定义域内，与任何 score 无关。
   - **不能预测幅度**：D10 是同一场景内 49 候选的排序 + 动作/成本决策，分解是单状态标量 score 在 A/B/AB quartet 上的一致性；两者无共享场景/parent。不得写"分解预测到了 0.4884 / 0.1455–0.3239 / 45.7%"。
   - **不得反推"概率本身有问题"**：R09-B 的同覆盖读数 1 正好是反证。
   - 若 r09 lane 同意，可在附录加一句**边界句**（不构成新 claim，不得与 r09 自己的 D10 文字重复或冲突）："在 D10 的场景宇宙里，117/256（45.7%）的场景对全部 49 个候选都不可行，这类场景没有正状态，S/J/J\* 分解在定义域上无法处理；分解能定位的是覆盖/工作点段，而不是不可行份额。"
5. **typed（任务适配）encoder 类在新任务上的同口径结论** —— 未做（发布的 typed 检查点没有独立特征头），不能用 raw/six 的结果代替。
