## 总判定

**可以进稿的部分（附录诊断段，最多 3–4 句）**：一个「静态置信不保证编辑后正确」的口径说明——把保留集定义在**起点**（未编辑父场景）logit 上而不是终点 logit 上之后，高起点置信子集上的编辑风险仍然是 keep 10–17%、flip 5–26%；并且这个诊断没有给 N01 的 matched 辅助监督带来任何额外收益证据。

## 可用片段 A（附录 · 方法口径）：P1 的保留集必须用起点置信

> 风险分解（P1）在**预测时可得的起点状态**上定义高置信集合：对每个 quartet，保留判据为 `|lg0| ≥ τ`，其中 `lg0` 是未编辑父场景渲染的 logit，`τ` 取该模型在 dev 单状态 bank 上 `|logit|` 的 2/3 分位（逐模型固定，不使用测试集）。同一 parent 的多个 quartet 共享同一起点图像与起点 logit。保留集随后用于两个互不混用的分母：**无条件 endpoint 风险**（仅在保留集上取错误率）与 **start-correct 条件下的 update 风险**（保留集 ∧ 起点判对）。实际覆盖率按实测值报告。

**可以说**
- 「保留集定义在起点 logit 上；同一 parent 的起点 logit 唯一」（12/12 run 内脚本断言成立）。
- 「实测覆盖率不是固定比例」：159 quartet 上 0.220–0.528（三种阈值分位下 0.182–0.635）。
- 「无条件与 start-correct 两套分母都报出」：在四臂上起点准确率 0.981–1.000，且所有起点判错的 quartet 都落在保留集之外，因此本矩阵中两套分母 12/12 行数值与 n 完全相同；这只是「高起点置信 ⇒ 起点判对」在本任务的巧合，不能推广为一般等价。

**不可以说**
- 不能说「我们保留的是 top 25%」——覆盖率是实测的，且逐臂不同。
- 不能把 D2（无条件）的数字当作 D3（start-correct）使用，反之亦然。

## 可用片段 B（附录 · 诊断结果）：高起点置信不降低编辑风险

> 在 159 个 quartet（74 parent）上，四臂的高起点置信子集里 keep（两个原子编辑保持标签）错误率为 0.100–0.171，flip（组合编辑翻转标签）错误率为 0.049–0.259；与之相比，不做保留筛选时的对应错误率为 keep 0.101–0.167、flip 0.069–0.189。即高起点置信在 9/12（keep）与 6/12（flip）个 run 上并不低于全样本，起点置信是静态识别置信，不是编辑后仍正确的保证。作为对照，若按终点状态自身的 `|logit| ≥ τ` 定义保留集，错误率会被压到 keep 0.000–0.044、flip 0.000–0.012——这正是把保留集建在终点 logit 上会得到的误导性乐观口径。

**可以说**
- 「在本任务与所测学生范围内，起点高置信子集的编辑风险与全样本同级，未系统性更低」。
- 「口径选择本身会改变量级：终点自置信口径把风险报成 ≈0」。
- 数字范围与分母：159 quartet / 74 parent；四臂 × 3 seed；保留集 n 见 `n01_p1_denominator_table.csv`。

**不可以说**
- 不能说「起点置信没有信息」：本诊断只比较了「保留 vs 不保留」的错误率，没有做校准曲线或风险—覆盖曲线。
- 不能把该现象推广为「所有高置信子集都有同样风险」：只测了本渲染合同、本任务、ResNet18 学生。
- 不能把终点自置信的 ≈0 当作「P1 风险确实很低」。

## 可用片段 C（附录 · 与 J/修复/迁移同表）：matched 在 P1 维度没有额外差异

> 在同一张表里并列 J、baseline110 的 full repair、migration、111 退化与 P1 指标：matched 相对 ordered 的 ΔJ 全样本 seed 均值为 −0.004（3/3 seed 的 parent bootstrap 区间含 0），P1 上 Δkeep 错误 −0.012、Δflip 错误 +0.025（0/3 区间排除 0，符号在 seed 间翻转），full repair 为 3/12、1/10、3/12，migration 为 0/0/0；matched 相对 BCE-only 的 ΔJ 为 +0.008（0/3），Δkeep 错误 −0.014、Δflip 错误 +0.005（0/3）；matched 相对 shuffled-matched 的 ΔJ 均值 +0.021，仅 seed803 区间排除 0（+0.132 [+0.037,+0.233]），另两个 seed 为负。所有 P1 配对比较均在两臂保留集交集（25–63 quartet，11–30 parent）上计算。

**可以说**
- 「matched 的辅助目标更可学，但在 J、full repair、migration 和 P1 四个维度上都没有一致的额外收益」——这正是 N01 判定 `NOT_SUPPORTED_BY_THIS_RECIPE` 的补强证据。
- 「matched − ordered 在 P1 上没有可判定差异」（0/3 seed 区间排除 0）。
- 「matched − shuffled-matched 的 +0.132 只在 1/3 seed 出现，不能作为机制证据」。

**不可以说**
- 不能说「匹配失败 ⇒ 关系迁移不可能」：本 lane 只否定所测学生/配方下的方法收益。
- 不能把 seed 均值当总体效应，也不能用三个 seed 充当三次独立确认。
- 不能引用 matched_s806 的 P1 点值（保留集仅 35 quartet / 16 parent）作外推。

## NOT_FOR_PAPER 清单

1. **「匹配辅助监督在 P1 / 高置信子集上有效」** —— P1 维度 0/3 seed 可判定，matched 相对 ordered/BCE-only 无一致差异。
2. **「高置信样本的编辑风险更低」** —— 实测在同级甚至在 9/12（keep）、6/12（flip）run 上更高；不能反过来说风险更低。
3. **任何用终点置信得到的 P1 数字** —— 终点自置信口径把风险压到 ≈0，只能作为口径对照写在方法说明里，不能作为结果。
4. **「top 25% 高置信集」这类表述** —— 覆盖率是实测值（0.220–0.528，随阈值分位 0.182–0.635）。
5. **把 159 quartet 当 159 个独立样本 / 把 3 个 seed 当 3 个独立任务** —— 159 行来自 74 个物理 parent，每 parent ≤4；bootstrap 只覆盖 parent 抽样不确定性。
6. **本 lane 的新计算被描述成「已有产物」** —— dev 阈值需要一次 CPU 前向（12 臂 × 707 张，约 2 分钟），checkpoint 来自回收包并已 hash 校验；commit/命令/hash 见 `artifacts/e1a933_review/vision_n01_p1/PROVENANCE.json`。
7. **本 lane 完成 ≠ 整个施工包完成** —— 这里只补上 N01 的 P1 诊断缺口，N01 的其余边界（单渲染合同、单学生、单任务）不变。
