本 lane 的结论**不足以支撑一条独立的部署增益主张**；它主要提供一条范围/限制陈述。逐条判定见下。

## 1. 可以进稿（限制段或附录，条件性）

**句 1（范围与分母）**
“决策前沿分析建立在 oracle 可行场景子集上：全部 256 个场景中 139 个（54.3%）至少存在一个可行候选，117 个（45.7%）完全没有可行候选。”

**句 2（外推，不是同覆盖）**
“把在 dev（43 个可行场景）上按目标覆盖 0.5 选出的阈值不加任何可行性筛选地外推到其余 213 个场景（其中 117 个 oracle 不可行，占 54.9%）时，实测覆盖为 0.1455–0.3239，而非 dev 的 0.4884；动作内成功率为 0.2239–0.9459，每场景净收益为 0.0322–0.1382（同场景自助 95% CI 全部为正，分母 213 场景）。因此这些数字只能称为 dev 匹配策略的外推，不能称为同覆盖已实现。”

**句 3（不可行场景的处置与后果）**
“在 dev 覆盖预算 0.25 与 0.5 上，使用关系特征编码（rel12/sixdist）的策略对 117 个 oracle 不可行场景全部拒动（0/117，成本占比 0.0）；raw 编码的策略在预算 0.25 时动 0–11 个、预算 0.5 时动 4–25 个，后者把 15.7%–48.3% 的总成本花在这些注定失败的场景上。把预算推到 1.0（近乎全执行）时所有策略都大量动作，不可行场景吃掉 14.8%–93.0% 的总成本，每场景净收益变为 −0.033…+0.189（raw 的 6 个策略中 5 个为负）。”

**句 4（方法学提醒，可放附录）**
“决策阈值只在 dev 上选择；由于 dev 场景集本身是按候选可行性筛出的，其覆盖目标不能直接当作部署覆盖，覆盖-成本权衡在无筛选场景总体上的位置需要在同样无筛选的 dev 上重新标定。”

## 2. 不可以说（对应上面的句子）

- 不可以说“同覆盖已实现”或“dev 覆盖在部署上复现”：dev 0.4884 → 实测 0.1455–0.3239（仅为目标的 30%–66%）。
- 不可以说“决策前沿方法在部署口径下带来可用增益”：b0.5 时 flipmine−clean 的**每场景净收益差 0/9 对** CI 不含 0；只有动作内成功率差 4/9 对 CI 为正。净收益差要在 b0.75 才 6/9 对为正、b1.0 为 5/9 对为正，且这些预算之间阈值嵌套、方向不一致的 seed 仍在。
- 不可以说“全流程没有 oracle 依赖”：dev 场景集（43 个）仍是用 dev 标签按可行性筛出来的；R09-C 的“dev 端也不筛选”只是敏感性（评估宇宙也换成 170 场景，与主口径 213 场景不可直接比较）。
- 不可以说“这就是部署性能”或“真实决策效用”：净收益定义为“每场景 1 单位成功奖励 − 1×归档动作成本”，是说明性效用；没有任何足球/业务效用验证。
- 不可以说“数千个阈值提供了数千次独立重复”：每模型枚举 24,966–31,311 个断点，去重后为 1,700–1,934 个不同动作策略；它们嵌套且高度相关。置信区间只在场景维度重抽（2,000 次，每策略重算完整 ratio）。
- 不可以说“9 个编码×seed 组合是 9 个独立任务”：它们是 3 个编码 × 3 个训练 seed。
- 不可以说这些是“新确认”：全部是同一批 256 场景上的再分析。

## 3. NOT_FOR_PAPER

**R09-B 的 oracle 标签诊断前沿**：作为“结果”NOT_FOR_PAPER。
理由：它的阈值枚举与“最优点”选择都使用 eval 标签，数值是乐观上界且**没有有效置信区间**（选择偏差无法由同一批数据自助估计）。
可进稿的唯一用法：在附录作为诊断性说明，且必须同时写出“该上界由 eval 标签挑选、不可部署”，并只允许引用以下不带 CI 的量：
- 固定覆盖下，dev 选出的阈值与同覆盖 oracle 点的每场景净收益差 ≤0.0093（最大 raw_s11 flipmine；多数 |差| ≤0.001，个别为负 −0.0067/−0.0037，因为同覆盖点按最近覆盖挑）；
- 未约束 oracle 的最优净收益主要靠覆盖而非阈值微调（rel12/sixdist 为 0.1531–0.2892，出现在覆盖 0.2394–0.4085；raw 只有 0.0528–0.0921）。

**R09-C 敏感性**：不作为正文数字（宇宙不同，170 场景 vs 213 场景）；只在方法学讨论里说明“覆盖塌缩部分来自 dev 端筛选目标错位”，并标明它仍未消除 dev 侧 oracle 成分。

## 4. 一句话总结（若只需一句）

“决策前沿的全部数字都以 oracle 可行场景为条件：把 dev 选定的策略原样外推到无筛选的 213 个场景时，实测覆盖从 dev 的 0.4884 掉到 0.1455–0.3239，117 个 oracle 不可行场景占该总体的 54.9%，低预算下关系编码策略对其全拒动、raw 策略则把 15.7%–48.3% 成本花在其上；因此该前沿只能报告为条件诊断与外推，不能报告为同覆盖的部署结果。”
