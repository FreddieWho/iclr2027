## 0. 结论摘要

**核心问题的明确回答：是——typed 相对 distance(six) 的劣势在匹配容量＋匹配优化后仍然存在。**

- 参数匹配（把 typed 缩容到 6681 参数，与 raw/six 的 6529–6849 相差 ≤2.5%）**完全没有改善 typed**：T1 flip J 均值 0.2403（匹配前 typed_o 0.2414），T2 0.2691（匹配前 0.3126）。缩容 30.1% 参数后 typed 没有变好，个别 seed 反而更差。所以"typed 参数多 39.5–46.3%"不能解释 typed 的劣势。
- 优化预算匹配（把同一批 lr×steps 候选**同等**给 raw/six/typed_m，用 train-only 目标选配方）**也没有消除劣势**：six − typed_m 的配对差在 T1 为 +0.499/+0.507/+0.505（三 seed），在 T2 为 +0.645/+0.675/+0.667；等配方下分别是 +0.514/+0.529/+0.486（T1）与 +0.731/+0.701/+0.755（T2）。全部 parent 配对 bootstrap 95% CI 远离 0（分母见 §5/§6）。
- **但机制被改变了**：typed 的劣势不是"容量过大"，而是**在单编辑监督上根本拟合不下去**。等配方下 typed_m 的最终训练目标（BCE(clean)+BCE(单编辑翻转)）为 0.25–0.50（T1）/ 0.25–0.26（T2），而 raw/six 为 0.006–0.021（T1）/ 0.0003–0.0010（T2）；把预算加大 10 倍并降 LR 后，typed_m 最好也只到 0.0804（T1）/0.00256（T2），而 raw/six 达到 3e-5–7e-5（差 10²–10³ 倍）。**在测试的配方空间内 typed 无法拟合它自己的训练目标**，这一点在匹配容量后依然成立。
- 同时，raw/six 在**所有**配方下都把训练目标压到 ~1e-4（完美拟合 clean + 全部 2728/2468 条单编辑翻转），J 却几乎不变（raw T1：等配方 0.2172 → 最优配方 0.2173；six T1：0.7498 → 0.7446）。所以 raw 与 six 之间 50pp 的差距**不是**优化/预算问题，而 typed 与 six 之间 50–73pp 的差距**首先是拟合失败**、其次是残余的表征/泛化差距。

因此 O02 的阴性结论（typed 结构不如成对距离输入）在排除参数与优化预算混杂后**仍然成立**，且理由更精确：不是"参数多所以更差"，而是"该对称池化结构无法拟合单编辑翻转监督"。

**选择"缩容 typed"而不是"扩容 raw/six"的理由**：需要排除的混杂方向是"typed 参数更多 → 更难优化"；raw/six 参数**更少**却更好，扩容只会让优势方更强，无法解释 typed 的劣势。缩容还保持 raw/six 臂与主表**逐字节相同**（§7 已验证），使匹配对照可直接与已发表数字对照。缩容后三组参数量相差 ≤2.5%，满足"参数数量可比"。

### 1.3 优化预算

- **等配方（primary）**：Adam lr=1e-2，300 步 full-batch，BCE，λ=1.0，clean 场景 ＋ 单编辑翻转对（与历史 U10 配方逐项相同，`docs/e1a933_review` 施工卡要求的"同一 steps/同一 LR 预算"）。四臂 = raw / raw+flip / six / six+flip，外加 typed_m / typed_o 的 clean 与 flip 臂。
- **最优配方（辅助）**：候选格 = lr ∈ {1e-2, 3e-3, 1e-3} × steps ∈ {300, 3000}，**raw、six、typed_m 各拿同样 6 个候选**（候选预算相同，不是只给 typed 加料）。
- **选择规则（train-only）**：对每个 (task, arch)，取 flip 臂在三个 seed 上**最终训练目标**（BCE(clean)+BCE(单编辑翻转)）均值最小的配方。**从未使用 E-J 选 epoch/超参**。为透明起见，JSON 里另存了"若按 J 选会选哪个"（`J_argmin_descriptive`），仅作描述、不参与任何比较。
- **"single-dev 拟合"的口径说明**：本 bank **没有独立 dev 划分**（train 512 场景来自 seed 10101，E-quartet bank 来自 seed 20202/40404）。因此可用的 train-only 拟合诊断只有 (a) clean 场景 BCE/acc、(b) 单编辑翻转对 BCE/acc。本报告用 (a)+(b) 作为施工卡所说 "train loss 与 single-dev 拟合" 的可实现替代；没有引入任何测试集信息。这是本 lane 对施工卡措辞的必要具体化，不改变选择规则的精神（只看训练侧拟合）。

### 1.4 计算纪律

- 三 seed（11/23/47）**全部保留**，包括弱 seed（例如 T1 six flip s47 = 0.7272、T1 typed_o flip s23 = 0.2258、T2 typed_o flip s11 = 0.2495）。没有剔除任何 seed、没有换分母、没有按结果筛条件。
- 每个臂保存：源码 commit、源码 sha256、bank sha256、init state hash、checkpoint sha256、真实命令、lr/steps/λ、逐样本分数、loss 曲线、最终拟合指标（`train_provenance.json`、`checkpoints/*/training.json`、`{T}_arm_scores.npz`）。
- 配对统计：`data_stats.parent_bootstrap`，按 parent 重采样 2000 次，quartet 加权，seed 933（与 R01/R02 同一实现）。

> 口径说明：上表引用的 `final_objective` 是训练循环最后一步**更新前**的目标值（`training.json` 字段），而 `diag` 分解是在最后一步更新**后**测的，两者可差一个 step（例如 T1 typed_m s11：0.5048 vs 0.5156）。同口径比较不受影响；本报告表内不混用两种口径。

**这直接给出机制解释**：typed 在历史配方下就没有拟合好它的训练目标（拟合不足），而不是"参数太多而过拟合"。

> **重要区分（防止误读日志）**：clean 臂的 `single_bce` 是**诊断量、不是该臂的目标**。clean 臂只在 clean 场景上训练，而 bank 里的单编辑是**翻转标签**的编辑，所以一个完美拟合 clean 的模型在这些编辑状态上会自信地预测原标签 → 诊断 BCE 自然很大（raw 11.14、six 5.81、typed_m 7.21、typed_o 9.44）。这是构造决定的，**不是发散**。真正判失败的依据是 §7 的 flip 臂目标。

| T2 特征优势 | +0.3918 / +0.3575 / +0.3564 | +0.3901 / +0.3549 / +0.3575 | 基本不变 |
| T1 I | +0.3935 / +0.4394 / +0.4126 | +0.3891 / +0.4196 / +0.4211 | 基本不变 |
| T2 I | −0.1891 / −0.1719 / −0.2504 | −0.2036 / −0.1879 / −0.2774 | 仍为负 |

**读法**：给 typed 更强的优化（10 倍 steps + 降 LR）确实让它变好一些（T2 J 均值 0.2691→0.3366），所以"typed 更难优化"这个方向**部分为真**；但这只把差距从 72.9pp 缩到 66.2pp，CI 依然远离 0。同时给 raw/six 同样的候选预算后它们几乎不动（raw T1 0.2172→0.2173、six T1 0.7498→0.7446；raw T2 0.6296→0.6314、six T2 0.9982→0.9989），说明历史配方对 raw/six 已经处于性能平台，原始比较不是被预算饿出来的。

## 7. 失败/退化配置完整披露

判定用 flip 臂的最终训练目标（clean 臂见 §3 的说明，其 `single_bce` 是诊断量，不参与判定）。

**(a) 单 seed 发散/高度不稳定（同一配方内跨 seed 目标差 >3 倍且绝对值大）**

| task | arch | 配方 | 三 seed 目标 | 说明 |
|---|---|---|---|---|
| T1 | typed_m | `lr01_s3000` | 0.3583 / **0.9784** / 0.2834 | s23 几乎完全不收敛；J 均值掉到 0.1393 |
| T2 | typed_m | `lr01_s3000` | **0.8605** / 0.0604 / 0.0004 | s11 几乎不收敛；J 均值 0.2228 |
| T1 | typed_m | `lr003_s3000` | 0.0302 / 0.0616 / 0.1495 | 选中配方，但仍比 raw/six 差 10³ 倍 |
| T1 | typed_m | `lr001_s3000` | 0.2623 / 0.0633 / 0.0348 | 跨 seed 抖动 7 倍 |

**(b) 欠拟合（300 步 + 小 LR）**：raw `lr003_s300`（0.0524）、raw `lr001_s300`（0.3088）、six `lr001_s300`（0.0580）、typed_m 全部 300 步配置（0.3512 / 0.4739 / 0.7153）。这些配置的 J 也相应更低（例如 T1 raw `lr001_s300` J 0.1718）。

**(c) 所有 typed_m 配置都没能把训练目标压到 raw/six 的水平**：最好 0.0804（T1）/0.00256（T2），而 raw/six 是 3e-5–7e-5。这不是"某个失败配置"的问题，而是该架构在整个候选格上的系统性拟合上限。

**这些配置如何处理**：
- 它们**不参与选型**（选型规则是最小化训练目标，自动排除 (a)(b) 类）；
- 它们在 `O02_BUDGET_MATCH.json` 里全部保留，含逐 seed 目标与 J，不删除、不改名；
- 报告主表用 §4 的等配方（全部架构同一配方）与 §5 的 train-only 选中配方，**不使用**任何 (a) 类配置。

**"最优配方比较"与"等配方比较"严格分开**：
- §4 是**等配方**：raw/six/typed_m/typed_o 全部 lr=1e-2、300 步 —— 回答"typed 的劣势是否只是更难优化"的那张表。
- §5 是**最优配方**：各自 train-only 选出的配方，仅作辅助。
- 两者给出同一结论，且 §5 的差距（T1 50.4pp、T2 66.2pp）与 §4（50.9pp / 72.9pp）同向同量级。

## 8. 数值执行顺序敏感性（发现的额外事实，必须披露）

历史 U10 的两批权重来自不同线程数：`u10_targets.py` 用 4 线程训练 raw/six，`data_u10.py` 用 2 线程重训 typed。本次复核发现线程数会改变浮点归约顺序，进而改变训练轨迹：

| 检查 | 结果 |
|---|---|
| 4 线程复跑 raw/six（历史配方）vs `artifacts/f095_campaign/U10/*` | **逐字节相同**（36/36） |
| 4 线程复跑 typed_o vs `artifacts/e1a933_review/data_u10/*_typed_s*` | 不同（最大权重差 2.8；逐 seed J 差最大 9.0pp） |
| 2 线程复跑 typed_o vs `data_u10/*_typed_s*` | **逐字节相同**（18/18） |
| 2 线程复跑 raw/six vs 历史 | 不同（符合上面的解释） |

2 线程整批复现（`data_u10_o02_numorder2/`）给出的逐 seed |ΔJ|：raw ≤0.011、six ≤0.022、typed_m ≤0.023、typed_o ≤0.090。也就是说 **typed 的 flip 臂对数值执行顺序敏感（单 seed 最多 9pp）**，但 six − typed 的差距是 65–75pp，比这个抖动大一个量级，因此 §0 的结论不受影响。本报告主表（4 线程批）内部完全一致：所有架构、所有配方在同一线程设置下训练与评估。

这条也是"可复现性"披露：历史 `data_u10` 的 typed 数字只能在 2 线程下逐字节复现；4 线程下同一配方同一 seed 会得到不同的 typed 权重。**不得**把两个线程设置下的 typed 数字混在一张表里比较。

## 9. 未完成与边界

1. **未做**（施工卡标为可选的难度/手性任务）：O02 卡第 5 条"新难度区间扫描"与第 6 条"手性边界任务"未执行（NOT_RUN）。审计已明确这两项是可选而非必欠；本 lane 只补必欠的参数/优化预算匹配。
2. **"single-dev" 的具体化**：本 bank 无独立 dev 划分，选择只能用 train-only 的 clean/单编辑拟合（§1.3）。若父 agent 认为必须有一个真正的 dev 划分，那需要新建 split，属于新 bank 设计，不在本 lane 范围。
3. **typed_m 的宽度是单点选择**：只用 w=40（6681 参数）。没有扫 w=36/44 来确认"匹配容量"的结论对宽度不敏感。三组参数量差异 ≤2.5%，但参数**分布**不同（typed 的 phi 是 2→40 的浅层共享分支），本 lane 不能排除"参数分布"而非"参数数量"的影响。
4. **T2 的 typed_m 选中配方（`lr001_s3000`）跨 seed 目标抖动 0.0013–0.0042（3 倍）**，说明该架构的最优配方本身不稳定；T2 的"最优配方"结论只能作为辅助证据，主结论仍应引 §4 的等配方表。
5. **容量匹配只在"缩容 typed"这一个方向做**。没有做"扩容 raw/six 到 9553 参数"的对照（理由见 §1.2）。若审稿人要求双向匹配，需要补一组 `CoordMLP(hidden=79)` 的臂。
6. **本 lane 只覆盖 O02 的必欠项**；施工包整体的其余缺项（R03 血缘、R09 部署范围、O01 训练路径因子、O04 前瞻干预、N02 迁稿、R10 状态同步）不在本 lane 内，本 lane 完成不等于施工包完成。
7. **数值执行顺序敏感性只在 2/4 线程两点上测过**，未做更多线程数/不同 BLAS 的扫描；也不能断言 9pp 是上界。
8. 本 lane 的所有数字都来自**已暴露的历史 bank**（再分析＋新训练），不是独立的新任务确认；不得表述为"未见首读的确认"。
