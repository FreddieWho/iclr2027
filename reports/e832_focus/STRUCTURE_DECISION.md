# 结构对比：L015 增益的三个解释

这不是新方法。比较的是三个已经混在一起的解释：缺跨段交互、多了中点距离和绝对正弦、以及现有 G8 排序。源任务只做到这里，没有开始 T1/T2。

## 结论

两个预先指定的对比都在同一新 parent 银行、同一训练合同上算完，并带 parent bootstrap 区间。seed 不是数据集，下面不把 seed 合成一个区间。8 个群元也不是重复样本。严格不变模型的零标签摆动是构造，不是新发现。

**被分开的解释：G8 排序，而不是“多出来的中点/角度量”。**

`rich8_sorted` 与 `rich8_unsorted` 使用同一 MLP（6849 参数，每例 6688 MAC），输入是同一组 8 个连续量：两段长、四条跨段距离、中点距离、绝对正弦。差别只是 `experiments/e1a933_review/leads_l014_l015_l006.py` 里现有的 G8 排序。single-flip 下，`sorted_minus_unsorted` 的 `delta_J3` 在 seed 11/23/47/71/83 都为正，5 个 parent 95% 区间都不含 0。点估计约 +0.061 到 +0.092，分母都是 2188 个 E、871 个 parent（`artifacts/e832_focus/structure/metrics_continued.json`）。因此，在这份具体不变处理上，排序还有额外的 `J3` 效应，不能把历史 G8 优势写成只是多算了中点和角度。

这个对比不证明两种表示的信息完全相同。排序可能碰撞、丢掉关联。这里只能说是这一次具体排序，不是完备商空间表示。

clean 监督下，同一对比有 4 个 seed 的区间不含 0 且为正；seed 11 的区间跨 0（点估计 +0.0265，区间约 [-0.0049, +0.0591]，同样 n=2188 / 871 parent）。clean 上不能写成每个 seed 都排除 0。single-flip 才是已经分开的那一侧。

**被分开的解释：缺一次段和后的非线性，不足以解释几何增益。**

旧加性 `TypedPairMLP` 仍是负控。第一修法只把段和之后的线性 `rho` 换成 `Linear-GELU-Linear`（k=16），保留段内角色和段交换对称，没有为了对齐参数删掉这层。它的训练损失下降了：6 个 seed×监督格子的最佳平均训练 BCE 都低于 0.60（`artifacts/e832_focus/structure/rho_optimization.json`，`failed=false`）。因此没有改用对称双参数 `q`。这只说明梯度走得动，不是银行泛化。

相对加性负控，clean 上 5 个 seed 的 `repaired_rho_minus_additive` `delta_J3` 都为正且区间不含 0，但只有约 +0.012 到 +0.032（n=2188 / 871）。single-flip 上 5 个 seed 里 3 个区间跨 0，两个不含 0 的也只有约 +0.010 和 +0.015。修后 `J3` 仍在大约 0.017–0.046。同一分母上，6 个有序距离的 single-flip `J3` 约 0.40–0.42，排序后的 8 维约 0.52–0.54。所以“旧网络段间可加”可以解释它为什么拟合不了棋盘，不能解释 L015 那种几何增益。修法抬了一点 clean `J3`，没有把 single-flip 变成联合正确。

加性与修后模型的 `AB_accuracy` 在 single-flip 下大约 0.57–0.62，但 `atomic_joint` 大约 0.35–0.42，`J3` 仍接近 0.02。修法不是“只抬 AB、不抬 J”的成功修复；两套分段网络的联合正确都低。

**没有被分开的解释：中点距离和绝对正弦本身。**

`unsorted_minus_sixdist` 在 seed 11/23/47 上，clean 的三个区间都跨 0；single-flip 只有 seed 47 的区间不含 0，另外两个跨 0。点估计大约 -0.020 到 +0.038（`artifacts/e832_focus/structure/metrics_3seed.json`，n=2188 / 871）。这不是预先规定要加 seed 的对比，所以没有改分母，也没有补 seed 71/83。不能说多出来的中点/角度量已经被单独证成，也不能说它被单独否定。

6 个有序距离已经远高于 raw（single-flip `delta_J3` 约 +0.33 到 +0.35，三个 seed 的区间都不含 0），但没有把任务做到顶：排序臂仍更高，没有任何臂的 `J3` 接近 1。因此不把测试改难，也不把 6 距离写成已经解决。

表示×监督交互 `I` 大多跨 0。排序优势主要是边际 `J3` 差，不是一个已经分开的监督交互。修后减加性的 `I` 接近 0 或略负，single-flip 没有让修法比加性多得好处。

## 训练合同

- 只训练 `artifacts/f095_campaign/D01/scenes_N/scenes.npz`。
- 监督两种：clean-only；clean 加全部保留的 single-flip。flip 挖掘沿用 O01：`candidates_for_scene`，`d03` oracle，每 parent 最多 12 条，seed 5。这是监督，不是主张分母。保留 flip 1534 条。没有做 25% 剂量，也没有把历史 checkpoint 当成 2×2。
- 选择：Adam 学习率 0.01 / 0.003 / 0.001，300 步全批。每个 arm×seed×监督只按 pooled static+single dev BCE 取最小；平手取更小的学习率。dev 是 256 个 clean parent 加 721 个 single-flip，分母 977，不用测试 `J3`。选择记录在 `artifacts/e832_focus/structure/selection.json`。

- 旧加性网络用了同一组 3 个学习率，然后停止。没有为了让它看起来学会而加优化器或加长训练。
- `torch.set_num_threads(4)`。不要把这些权重和 2 线程历史权重逐位比较。

## 修复流向

固定基线是同一 seed 的 raw clean，不是各臂自己的 clean。`R_endpoint`、`R_full`、`M` 的条件集是该基线的 110：A 与 B 对、AB 错。`regression111` 的分母是该基线的 111。恒等式 `R_endpoint = R_full + M` 在未舍入均值上成立，残差约 0。数字在 `metrics_3seed.json` 的 `flows`，`source=raw_clean_same_seed`，监督为 flip。

| seed | 基线 110 / 111 | arm | `R_endpoint` | `R_full` | `M` | `regression111` |
|---|---:|---|---:|---:|---:|---:|
| 11 | 1217 / 93 | `repaired_rho` | 0.530 | 0.015 | 0.515 | 0.989 |
| 11 | 1217 / 93 | `sixdist` | 0.718 | 0.447 | 0.271 | 0.473 |
| 11 | 1217 / 93 | `rich8_unsorted` | 0.758 | 0.449 | 0.309 | 0.495 |
| 11 | 1217 / 93 | `rich8_sorted` | 0.785 | 0.532 | 0.253 | 0.462 |
| 23 | 1185 / 128 | `rich8_sorted` | 0.792 | 0.538 | 0.254 | 0.375 |
| 47 | 1228 / 99 | `rich8_sorted` | 0.787 | 0.564 | 0.223 | 0.465 |

几何臂的端点改善同时包含完整修复和迁移，不是只剩迁移。分段网络在同一 110 上的 `R_full` 约 0.01–0.03，`M` 约 0.47–0.59：AB 变对时，原子项经常被破坏。111 回归的分母只有 93–128，不能单独支撑强结论；它只说明 raw clean 里少数已经联合正确的 E，分段网络几乎都退回去了。

各臂自己的 clean 到 flip 流向另记为 `source=within_arm_clean`，没有拿来替换上面的固定基线。

## 不变性

`additive`、`repaired_rho`、`rich8_sorted` 在 64 个 A 状态上的 G8 logit 最大摆动是 0。这是结构和特征的构造结果，不是 8 次独立复制。`raw`、`sixdist`、`rich8_unsorted` 的同一诊断摆动大于 10。诊断分母是 64 个状态，不是 8×64 个复制。

## 没有做的事

- 没有训练对称 `q`。触发条件是训练损失不下降，不是测试 `J3` 低。第一修法的训练损失下降了。
- 没有把明显无效的臂跑到 10 个 seed。只对区间没有站在 0 同一侧的两个预先对比补了 seed 71 和 83。
- 没有做 T1/T2。源任务上“段间加性不够”不能自动推到其他任务。
- 没有用 `dev512`，没有读封存池，没有租 GPU。本机没有 CUDA。
- 没有发明数值成功门槛。6 距离没有解决任务，所以没有把银行改难。

这一结果不修改 `PLAN`。它只是把已有 L015 比较里混在一起的三个解释拆开：排序处理有额外的 single-flip `J3` 效应；最小的段间非线性修复没有恢复该效应。
